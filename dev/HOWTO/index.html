    HOWTO

    The PINN-JAX framework aims to expedite the model construction process involved in the development of neural networks, particularly physically-informed neural networks.

    POTENTIALLY OUT OF DATE. SEE SPECIFIC FUNCTION DOCSTRINGS.#

    It follows an OOP approach, where users are expected to piece together previously defined classes, or create their own. It's important to note that the original intent of this package was to create physics-informed neural networks for metal additive manufacturing, and thus many architecture decisions were made entirely on that basis. Features surrounding other machine-learning approaches, such as CNNs or data-driven approaches, will be incorporated in time.

    1. Domain/Geometry/Time:#

    The first step of any problem is to define the model geometry. This comes in two forms Shape and Domain. Unfortunately, at the moment, some features are exclusive to one or the other.

    The Domain defines the bounds of the object given it's min and max values for 2D (x,y) or 3D (x,y,z), with an optional Time object for time-dependent problems. This, unfortunately, limits the definition of the domain to axis-aligned bounded boxes. Future additions of this package aim to modify the definition of Domain to alleviate this issue.

    The Geometry is defined by a series of Shape primitives, such as, Triangle, Rectangle and Box, and can be combined to create a ComplexShape. * Triangle is defined by 3 vertices (a,b,c) either in 2 or 3-dimensions. * Rectangle and Box are defined as an OBB. And requires an origin point and either 2 or 3 edge vectors.

    For convenience a Domain object can be converted to an OBB using the command .to_obb on the Domain object. Domain.from_obb() can be used to construct a Domain using an OBB. Naturally, this only works for axis-aligned OBB.

    Once defined, a Shape has a variety of features, namely, bounds, transform, estimate_nsmaples, normal, and draw. * bounds: returns the lower and upper bounds of the shape. * transform: is used to transform unit samples back into the domain of the shape. * estimate_nsamples: simply determines the necessary uniformly/grid-distributed samples based on a given res, or resolution. Many advanced sampling methods necessity user-defined sample sizes, so estimate_nsamples provides a baseline given the shape dimensions. * normal returns the normal vector of a shape. It's important that the shape is defined correctly using the right-hand rule in order for this to work properly. * draw plots the object, with an optional parameter to include the normal vector. Since every domain is different it's not expected the output is publication ready, however, it is useful for determining correct orientation.

    All Shape methods are used in the standard OOP format, for example, using draw:

    import pinnjax
shape = pinnjax.Box(origin=..., 
                edge1=..., 
                edge2=..., 
                edge3=...
            )

shape.draw()

    The Shape has a few additional methods, but they will be mentioned in the following sections as they become relevant.

    Note: Currently, the best way to access all features when using primitive shapes (Triangle, Rectangle, Box) alone is to pack them into a ComplexShape, i.e.,

    import pinnjax
time = pinnjax.Time(0, 10, 0.05)
domain = pinnjax.Domain(min=(0, 0), max=(3, 3), times=time)

obb = domain.to_obb()
rect = pinnjax.Rectangle(*obb, times=time)
geometry = pinnjax.ComplexShape([rect])

    2. NeuralNetwork/Activation/Optimization#

    The NeuralNetwork object defines the Type of all future neural networks, however there is only one defined function single_point which simply calls the model for a single point. This is important for jax.vmap which is detailed further in the section JAX and JIT-Compliance. Currently, only the feed-forward neural networks FNN has been predefined. For FNN, the class Activation object has been defined. This is simply a wrapper for jax.nn activations, which accept the activation callable and related *args & **kwargs. This acts as a simple way to carry and package the relevant parameters through various functions.

    The Optimization object, currently, holds 3 other objects InputTransform, OutputTransform, and HardConstraint, however these are directly used in the FNN object, and thus are not explicitly necessary for user-defined models.

    3. Residuals/DifferentialOperators/Loss#

    The Residual is an important part of the physics-informed neural network as it defines the discrepancy between the model and the expected physics, either in the form of a BoundaryCondition or PartialDifferentialEquation. Since the defining physics varies for every situation, this will need to be written entirely by the user. However, to ease this process, ensure functionality with the remaining codebase and, hopefully, stay jit compliant, some default practices should be followed.

    The Residual class encompasses two child-classes BoundaryCondition and PartialDifferentialEquation, however they are nearly functionally identical in this codebase. The distinction is primarily for the end user. To define a new Residual simply create a new Residual class with at minimum a _residual() function, which will act as the __call__ or define their own __call__.

    For example:

    import pinnjax
import jax
import jax.numpy as jnp
from jax import Array

class MyDirchlet(pinnjax.BoundaryCondition):
    def __init__(self, boundary_value: int | float):
        super().__init__()
        self.boundary_value = boundary_value

    def _residual(self, points: Array, ops: pinnjax.DifferentialOperators):
        def residual(u):
            T = ops.T(u)
            return T - self.boundary_value
        return jnp.nan_to_num(jax.vmap(residual)(points))

    The BoundaryCondition parent class defines the __call__ function, so:

    residuals = MyDirichlet(points, ops)

    will properly return the residuals. This format is important to maintain to ensure the proper usage of the Shape method: set_residual.# This function binds the Residual to a given Shape such that within a ComplexShape shape assign_residuals can be used to apply a different Residual to each shape.

    The logic for the example _residual function might seem counter-intuitive, however it's important for taking full advantage of 'JAX' and JIT-compilation. This will be expanded on in a later section: JAX and JIT-Compliance

    The _residual also requires an DifferentialOperator object ops. This is where all the definitions for automatic differentiation are stored. Unless more differential operators are required, the ops can be simply created as: ops = src.DifferentialOperators(model), where model is the NeuralNetwork. It's important that if the model is updated the DifferentialOperator is redefined, however, in the current train function, this is done automatically.

    Once the residual has been calculated, the loss must be calculated. For PINNs, this is generally the ResidualMSError and has been predefined.

    4. Sampling#

    Once the Shape has been defined, the collocation points can be sampled within using .samples() for ComplexShape and .sample() for a primitive shape. The method of sampling SamplingMethod object should also be defined. Currently, the only predefined SamplingMethod is SobolSampler which is a quasi-random approach which samples points in a predefined sequence. Many advanced sampling methods require a predefined number of points, however that can be difficult to determine methodologically in advance. Therefore, for simplicity, the number of points is balanced dependent on the number of sample required in a purely uniform/grid-based approach. Thus, the .sample() method requires a SamplingMethod object and a res uniform-sampling resolution.

    Though, since that is not the case for all sampling methods, this requirement aims to be phased out in the future.

    5. Pathing#

    Since this package was originally created for the purpose of simulating the metal additive manufacturing process, the path the heat source takes is an important part. Thus, while not useful in many cases, since a constructed Path can return the location of the path object, whatever it may be, at each time-step and the offset for all other points, its possible it may find use in other projects.

    Currently, 2 paths have been predefined the LinearPath and CirclePath, which traverse as per their namesakes. To create a path, this first requires the creation of a LinearPathConfig or CirclePathConfig object, which, when inserted as the only parameter of create_path() will construct the relative path.

    Once created, a Path should be validated using validate(:Domain) to ensure that all points along the path remain within the provide domain. Naturally, this only works for axis-aligned OBBs at the moment since it requires a Domain object. Also, using the Domain object, draw(:Domain) can be called on the Path object to display a quick plot of the path for verification purposes.

    import pinnjax
time: pinnjax.Time = pinnjax.Time(0, 2, 0.05)  # (min, max, time_step) [s, s, s]
domain =  pinnjax.Domain(min=(0, 0, 0), max=(0.04, 0.006, 0.003), times=time)

path_config = pinnjax.LinearPathConfig(speed=0.01, direction=(1, 0, 0), initial=(0, 0.003, 0.003))
path = pinnjax.create_path(path_config)

path.validate(domain)

    A Path object has two primary methods eval and offset and a well-structured custom path should follow the same template. * eval: returns the location of path in time when provided a time-step or series of time-steps. * offset: returns the spatial distance between a given point and the heat source at the time provided by the point.

    6. Train#

    The train function takes 3 inputs; the model (NeuralNetwork), the geometry (Shape) and training (Training). Currently, the Training parameters are limited to the number of epochs and the Optimizer object. The Optimizerobject simply acts as a wrapper for all optax defined optimizers, however since every optimizer has a different set of arguments and keyword-arguments it was deemed best to wrap these in an object which functions identically to the Activation object.

    The train function returns the updated model NeuralNetwork object.

    7. Prediction#

    Once the model has been trained it can be used for prediction. However, since advanced sampling methods were presumably used, the spatio-temporal sample space is almost certainly too sparse for high-resolution prediction. Thus, a Grid object should be created. The Grid object generates a uniform mesh based on a number of inputs and formats the samples properly for use in model prediction.

    The predefined Grids include: RectangularGrid3D, RectangluarGrid2D, and LineGrid.

    All three function similarly, and currently only with a Domain object.

    For LineGrid and RectangularGrid2D the user can provide a fixed_coordinates dict, which denotes which dimensional axis should constant and what value it should be constant for. For example:

    import pinnjax
time: pinnjax.Time = pinnjax.Time(0, 2, 0.05)  # (min, max, time_step) [s, s, s]
domain: pinnjax.Domain = pinnjax.Domain(min=(0, 0, 0), max=(0.04, 0.006, 0.003), times=time)

grid = pinnjax.RectangularGrid2D(
    domain=domain,
    fixed_coordinates={'z': updated_model.domain.max[2]},
    num_points=(300, 100)
)

    where the 3D domain would be sliced along the z-axis at z=0.003.

    Once a Grid object has been created, a prediction can be made with one of three functions: * predict: make a prediction using the trained model NeuralNetwork at the Grid points and time t. * predict_at_times: make a prediction at multiple times ts using predict. * prediction_evolution: predict a large number of times if the Grid was constructed including time constraints.

    grid = src.RectangularGrid2D(
    domain=updated_model.domain,
    fixed_coordinates={'z': updated_model.domain.max[2]},
    num_points=(300, 100),
    time_range=(domain.times.min, domain.times.max),
    num_times=105
)

    8. Plotting#

    The currently provided plotting functions were made with the RectangularGrid2D in mind and thus will not necessarily work as expected for custom grids. Though, despite not being generalized, plot_prediction and plot_prediction_evolution have been provided, and do as their name suggests. It's important to note that plot_prediction_evolution returns an animation.

    JAX and JIT-Compliance#

    The power of JAX is primarily stored in two places: vmap and jit. is the automatic vectorization for JAX. Instead of slowly looping through each instruction for each element, elements can be grouped together, and the instructions can be applied to the whole batch at once.

    The general format for vmap is to define a function that works for a single element, then pass that to vmap() followed by any parameters the single function requires. JAX works best when this is a single parameter, however, if there is need to pass multiple parameters its best done in the form of a PyTree or a NamedTuple.

    JIT, or Just-In Time, compilation acts as a midpoint between compiled languages; like C and C++, and interpreted languages; like Python and JavaScript. By compiling just in time, this code can be significantly faster than traditionally interpreted code. However, this requires the code to be well formatted. In particular, JAX requires array shapes to be static and known at compile time. JIT works by tracing a function to determine its effect on inputs, therefore variables that shouldn't be traces must also be marked as static.

    To use JIT with JAX append the decorator @jax.jit, within a class its best to instead use @eqx.filter_jit since it has logic to ignore the self object which @jax.jit will assume is a JAX array, unless marked as static.

    It's important to remember that JIT applies all the way downstream, so if @jax.jit is applied to an overarching function all internal functions should be properly formatted for JIT. Also, it's best to only apply the decorator to the outermost function. A JIT decorated function shouldn't have JIT decorated internal functions.

    Full Example:#

    import jax
import optax

import pinnjax
pinnjax.config.setup_clean_errors() # not-necessary, but clears the traceback for input related errors. 

if __name__ == "__main__":
    # Define Time & Domain 
    time: pinnjax.Time = pinnjax.Time(0, 2, 0.05)  # (min, max, time_step) [s, s, s]
    domain: pinnjax.Domain = pinnjax.Domain(min=(0, 0, 0), max=(0.04, 0.006, 0.003), times=time)

    # Define Problem Specific Objects
    goldak = pinnjax.Goldak(
        power=2.45e3,
        efficiency=0.9,
        width=0.006,
        front_ellipsoid_length=0.00257,
        rear_ellipsoid_length=0.006,
        depth=0.004,
        front_ellipsoid_distribution_factor=0.6,
        rear_ellipsoid_distribution_factor=1.4,
    )

    material = pinnjax.Material(
        heat_capacity=6.20e2,
        density=7.85e3,
        radiation_coefficient=0.2,
        thermal_conductivity=45,
        convection_coefficient=2e4,
        ambient_temperature=298,
        temperature_range=3000,
    )

    # Define Optimizations
    optimization: pinnjax.Optimization = pinnjax.Optimization(
        pinnjax.NormalizationBetweenNeg1and1(domain),
        pinnjax.ExpectedTemperatureRange(material),
        pinnjax.HardInitialConstraint(
            times=domain.times, initial_condition=material.ambient_temperature
        ),
    )

    # initiate the random key used for the model.
    key, subkey = jax.random.split(jax.random.PRNGKey(0), 2)
    # define topology and activation
    topology = (4, 64, 64, 64, 64, 1)
    # src.Activation(:Callable, :*args,: **kwargs)
    activation = pinnjax.Activation(jax.nn.gelu, kwargs={"approximate": False})

    # build a Feed-Forward Neural Network with the previously defined parameters. 
    model = pinnjax.FNN(
        subkey,
        topology,
        activation,
        domain,
        optimization,
    )

    # configure the linear path
    path_config = pinnjax.LinearPathConfig(speed=0.01, direction=(1, 0, 0), initial=(0, 0.003, 0.003))
    # create given path 
    path = pinnjax.create_path(path_config)

    # ensure that the path remains within the domain for all time-steps. 
    # if a path doesn't remain in the domain, the model will generally fail to train.
    path.validate(domain)

    # define the pde and boundary conditions (robin, dirichlet) and the loss function.
    pde = pinnjax.GoldakHeatFlux(material, goldak, path)
    robin = pinnjax.RobinHeatFlux(material)
    dirichlet = pinnjax.DirichletHeatFlux(material)

    loss_function = pinnjax.ResidualMSError()

    # define the sampling method
    sampling_method = pinnjax.SobolSampler()

    # convert the domain to an obb (origin, edge1, edge2, edge3)
    obb = domain.to_obb()
    # build a ComplexShape (BoundedBox) using the OBB. 
    geometry = pinnjax.BoundedBox(*obb, times=time)

    # bounded_box order : ['interior', '+x', '-x', '+y', '-y', '+z', '-z']
    residual_functions = [pde, robin, robin, robin, robin, robin, dirichlet]
    # assign the residuals to each of the shapes in the bounded box and the loss to the entire ComplexShape.
    geometry.assign_residuals(residual_functions)
    geometry.assign_loss(loss_function)

    # separation between points in uniform/grid sampling in meters
    resolutions = [0.0014, 0.001, 0.001, 0.001, 0.001, 0.001, 0.001]
    # sample in each of the shapes using the sampling_method at a given resolution.
    geometry.samples(sampling_method, resolutions)


    # define training parameters
    scheduler = optax.exponential_decay(
        init_value=1e-2, transition_steps=10, decay_rate=0.96
    )

    # build the Optimizer object containing the callable, *args, and **kwargs.
    optimizer = pinnjax.Optimizer(
        optax.adam,
        kwargs={"learning_rate": scheduler, "b1": 0.9, "b2": 0.999, "eps": 1e-8},
    )
    # build the training parameters object. 
    training = pinnjax.Training(optimizer, epochs=10)

    # train the model and return the trained model.
    updated_model = pinnjax.train(model, geometry, training)

    # build a grid for proper prediction. (rectangular 2D grid w/ time-dependency)
    grid = pinnjax.RectangularGrid2D(
        domain=updated_model.domain,
        fixed_coordinates={'z': updated_model.domain.max[2]},
        num_points=(300, 100),
        time_range=(domain.times.min, domain.times.max),
        num_times=105
    )

    # predict a single time step (1.5s)
    prediction = pinnjax.predict(updated_model, grid, 1.5)

    # predict all time-steps as defined in the Grid. 
    predictions = pinnjax.predict_evolution(updated_model, grid)

    # plot the single time-step.
    _ = pinnjax.plot_prediction(prediction, updated_model.domain, show=True)
    # plot the evolution as an animation.
    _ = pinnjax.plot_prediction_evolution(predictions, grid, show=True)
